name: Test fixes on real data before applying
description: Any code/strategy fix must be backtested on real live_ticks + recommendations data first; only apply if PnL improves
type: preference
---
قبل ما اطبق أي تعديل على كود الاستراتيجية (filters, stops, targets, breadth gates, scan logic):
1. اعمل محاكاة SQL كاملة وشاملة على **كل البيانات المتاحة** (live_ticks + recommendations + snapshots) ولا تكتفِ أبداً بعينات.
2. الاختبار يجب أن يشمل كل الأيام المسجلة في قاعدة البيانات لضمان عدم وجود حالات شاذة أو خسائر خفية.
3. قارن النتيجة الحالية بالنتيجة بعد التعديل بالأرقام الصافية (بعد العمولات والسيولة).
4. لو التعديل **يحسّن** PnL أو يقلل الخسارة بشكل حقيقي ومثبت على كامل المدى الزمني → طبّقه بعد إذن المستخدم.
5. لو التعديل **يسوّء** النتيجة أو محايد أو ناجح في عينات فقط وفاشل في غيرها → ماتطبّقش وقول للمستخدم النتيجة بالتفصيل.
6. ممنوع نهائياً الاعتماد على "عينات" أو "تخمينات"؛ الدليل الرقمي الكامل هو المرجع الوحيد.
7. الاختبار يجب أن يأخذ في الاعتبار معايير السيولة (150k EGP Bid) في كل صفقة دون استثناء.

**Why:** المستخدم تعرض لخسائر سابقة بسبب تعديلات "نظرية" أو مبنية على عينات مضللة؛ الدقة المطلقة والشمولية هما حائط الصد الوحيد.
