# DATA QUALITY SYSTEM — per-symbol-per-day reliability metadata

**Why this exists**: analyses kept confusing "the system is broken" with
"this illiquid stock didn't trade". This system makes every export
self-describing so no future analysis (by us or any AI) has to
reverse-engineer completeness again. Built Sep 5, 2026.

## Market-level vs symbol-level completeness — THE key distinction

- **Market-level completeness** = is the COLLECTION pipeline healthy?
  (extension running, marketwatch snapshots flowing, all ~275 symbols
  visible). Diagnosed on the /marketwatch-health dashboard. This is a
  SYSTEM question.
- **Symbol-level completeness** = is THIS symbol's data for THIS day
  trustworthy for backtesting? A stock that trades 2 times all day is
  COMPLETE data of a thin market — not a data-collection failure.
  Diagnosed by the quality flags below. This is a TRUST question.

Example of the exact confusion this prevents: a stock with 3 ticks that
stopped at 12:09 Cairo was flagged "reliability problem" by two separate
analyses. Ground truth (verified against full-market snapshots): the stock
traded 3 times all day. Collection was perfect; the market was thin.

## What is computed, and where

`src/lib/data-quality.server.ts` — pure computation, shared by all tools:

- `cairoOffsetMinutesFor(date)` — DST-aware Cairo offset via Intl
  (Egypt reintroduced DST in 2023; it is **UTC+3 in Aug–Oct 2026**, not the
  pre-2023 year-round UTC+2). NEVER hardcode an offset — one external
  analysis was burned by assuming +2 when the data was +3.
- `computeDayQuality()` — for each symbol in a day:
  - first/last tick (Cairo local), minutes from 10:00 open, minutes before
    14:30 close, total rows, max intraday gap during 10:00–14:15
    (the 14:15–14:30 closing-auction silence is normal market behavior and
    is EXCLUDED from gap measurement)
  - `OPEN_RELIABLE` — first tick within 10 min of open
  - `CLOSE_RELIABLE` — last tick within 15 min of close
  - `FULL_SESSION_RELIABLE` — both true AND max gap < 15 min
  - `likely_reason` when NOT reliable (see below)

## The three likely_reason values

1. **`possible_illiquidity`** — the symbol stayed visible in full-market
   marketwatch snapshots to end-of-day but simply had no trades.
   REAL market behavior; collection was fine. Backtest can use the day but
   the stock is thin — signals on it are noise-prone.
2. **`possible_collection_gap`** — the symbol was missing from marketwatch
   snapshots too (or no evidence was available). We may have LOST data.
   Do not backtest on this symbol-day without acknowledging the hole.
3. **`late_extension_start`** — the whole day started late (median first
   tick after 10:10 Cairo: browser/extension opened late). Not the symbol's
   fault; the day is truncated at the front for everyone.

Evidence rule (from the Sep 5 Stage-B audit): marketwatch snapshots cover
ALL ~275 symbols every 20–53s regardless of trading. If a symbol is visible
there to end-of-day, its missing ticks are illiquidity, not loss.

## Where the metadata lives

- **On disk**: `D:\1All Data\{table}\{date}.quality.json` — one companion
  per archived day, generated by `scripts/generate-quality.ts`
  (`bun scripts/generate-quality.ts` regenerates all; `--tables live_ticks
  --days 2026-09-02` for targeted runs). All existing days are already
  generated (Sep 5, 2026).
- **Unified CSV export** (`runExport`): the response now includes
  `qualityCsv` + `qualityReadme`; the UI auto-downloads
  `data_quality_{start}_to_{end}.csv` with the readme as `#` comment header.
- **MKB2 export** (`/api/public/hooks/export-binary`): appends a final
  `_quality` section (decoded as `_quality__{start}.csv` by the existing
  `scripts/decode-mkb2.cjs` — no decoder changes needed). Absent when no
  quality files exist for the range.

## Thresholds (all in `data-quality.server.ts` constant `T`)

| Constant | Value | Meaning |
|---|---|---|
| openTolerance | 10 min | first tick ≤ 10:10 Cairo = OPEN_RELIABLE |
| closeTolerance | 15 min | last tick ≥ 14:15 Cairo = CLOSE_RELIABLE |
| maxGap | 15 min | no intraday gap > 15 min (10:00–14:15) |
| lateDayStart | (median > open+tolerance) | marks late_extension_start days |

Tune these ONLY after a fresh canary-style validation run — they feed every
downstream flag.

## Backtesting rule (put this in front of any AI analyzing an export)

> Do not use non-reliable symbol-days for precise profit/loss backtesting
> without accounting for the likely_reason. Filter to
> `full_session_reliable=true` for clean studies, or model the reason
> explicitly.
